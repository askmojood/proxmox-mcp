# CLAUDE.md — proxmox-mcp

**Company context comes first: read [../mojood-master/CLAUDE.md](../mojood-master/CLAUDE.md) and
[../mojood-master/STATUS.md](../mojood-master/STATUS.md), then this file.** Never add a `Co-Authored-By` line (or
any Claude attribution) to a commit message or a pull request description.

**What's here:** a Mojood Connect demo, built for one company (Proxmox Server Solutions GmbH) to show them their
product working inside Claude. Six tools over Proxmox VE's REST API; the two that change guests (power, snapshot) need
a confirmation code (`tools.py`); nothing deletes, restores or rolls back. A local Proxmox VE 9.2 (official arm64
build) runs in a Lima VM called `pve` with nested KVM (`scripts/up.sh` installs it, `scripts/pve-install.sh`), and
holds the SAMPLE guests of the made-up Harbor Trading (`scripts/seed.sh`, run by `scripts/reset.sh`). Private until
Hammad sends it; public (Apache-2.0) after. Same recipe as `../snipeit-mcp`, but no Docker: Lima instead.

## Commands
```
scripts/reset.sh                         # local Proxmox (first run installs it, ~10 min) + fresh SAMPLE guests
uv run --env-file .env proxmox-mcp       # http://127.0.0.1:8008/mcp ; add --stdio for Claude Desktop
uv run --env-file .env pytest            # unit tests + live tests (run reset.sh first: live tests expect the seed)
uvx ruff check --line-length 120 src tests
limactl stop pve                         # free the ~6 GB the VM uses
```

## Rules
- Secrets (`.env`: the API token secret and the viewer's password) are generated by `up.sh`, git-ignored, and never
  printed, copied into docs or chat.
- Everything in the data is SAMPLE and made up.
- A change tool never acts without its confirmation code; keep the tests in `tests/test_tools.py` passing.
- Proxmox refreshes guest status every few seconds: `/cluster/resources` lags right after a start, so a change's
  result reads `status/current`, and `seed.sh` waits before it finishes.
- Unauthenticated requests get a slow 401 from pveproxy: probe with the token.
